## Аутентификация
Кастомный класс `User`, унаследованный от абстрактного класса `django.contrib.auth.models.AbstractBaseUser`, используется для систем аутентификации и авторизации. В нём реализованы методы сохранения в базе и проверки пароля с использованием сторонней библиотеки хэширования `bcrypt`. Методы используются для *регистрации*, *входа* в систему и для *обновления пароля*.

Кастомный класс `CustomJWTAuthentication`, унаследованный от абстрактного класса `rest_framework.authentication.BaseAuthentication`, используется по умолчанию в приложении для JWT-аутентификации пользователей, в котором токены управляются с помощью сторонней библиотеки `PyJWT`.

При входе в систему генерируется два ключа/токена:
- токен доступа `access token` с коротким временем жизни
- токен обновления токена доступа с длительным временем жизни `refresh token`.

Токен доступа хранится только у клиента и используется для аутентификации в системе, а токен обновления хранится у клиента и на сервере в БД. Для хранения токена обновления создана отдельная таблица.

При аутентификации проверяется три состояния:
- актуальность токен доступа,
- наличие токена обновления,
- активность пользователя -- атрибут `is_active`.

Выход из системы *logout* реализован через удаление токена обновления `refresh-token` из БД.

## Авторизация
Система разграничения прав доступа (система безопасности приложения) реализована с помощью подхода *RBAC*(role based access control) -- права доступа к ресурсам выдаются на основе ролей пользователей.

Схема управления состоит из следующих компонентов:

- таблицы в БД
    - **Role** -- роль пользователей
	    - *name* -- название роли (admin, teacher, parent, student).
    - **Resourse** -- типы объектов, над которым пользователь проводит действия
	    - *name* -- название ресурса (user, permission, graduate)
    - **Action** -- типы действий пользователя над объектом, CRUD
	    - *name* -- название действия (create, read, update, delete)
    - **Permission** -- комбинация ресурса `resourse` и разрешенные над ним действия `action` 
	    - *resourse* -- ссылка на ресурс
	    - *action* -- ссылка на действие
    - **UserRole** -- таблица назначения ролей пользователю
	    - *user* -- ссылка на пользователя
	    - *role* -- ссылка на роль
    - **RolePermission** -- таблица назначения разрешений ролям
	    - *role* -- ссылка на роль
	    - *permission* -- ссылка на разрешение
- кастомный класс `RBACPermission`, унаследованный от `rest_framework.permissions.BasePermission`, проверяет, есть ли разрешения `permissions` у данного пользователя `user` по наличию у него роли `role` для данного типа действия `action` над данным типом ресурса `resource`.
- один из способов применения системы авторизации это добавить `RBACPermission` в список классов разрешений `permission_classes` в класс представления `APIView`.
```python
class ProfileView(ApiView):
    permission_classes = [RBACPermission]
```
- для определения типа ресурса в представление `view` необходимо добавить атрибут `resourse` с названием типа ресурса. 
```python
class ProfileView(ApiView):
    resourse = 'user'
```

## Запуск
Для запуска проекта нужно переместиться в корень проекта и выполнить команду:
```sh
docker compose up --build -d
```

Веб-приложение запустится на локальном хосте на порту 8000.

Документация api доступна по пути `api/schema/swagger-ui/`.
Для проверки прав доступа в браузере нужно сделать следующие шаги:
- войти в систему по адресу `api/auth/login/`
- скопировать `access-token`
- нажать кнопку *authorize* и вставить токен
- теперь можно обращаться к ресурсам, проверяя систему авторизации
